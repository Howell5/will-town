# 首版架构建议

日期：2026-09-13。状态：技术提案，尚未安装依赖或实现应用。

## 选择依据

首版用于演示与验证：让访客看见一个有氛围的小镇，能走到店铺、了解产品，并打开产品链接。主要交互仍是网页内容与导航。

建议采用 TypeScript、React、Vite、Three.js 与 React Three Fiber，单仓库、单前端应用。React Three Fiber 是 Three.js 的 React 渲染器，便于把店铺、灯光、角色组织为组件；不额外引入游戏引擎。

Godot 具备适合游戏制作的场景编辑、物理和动画工作流，但当前范围主要是有限区域的移动、简单碰撞、入口触发和网页展示。为这些能力加入一套独立引擎及 Web 导出流程，收益有限。若未来核心玩法扩展到任务、战斗、复杂物理、关卡编辑或原生游戏发行，再重新评估。

Godot 可以导出到浏览器，当前稳定版文档说明 Web 导出依赖 WebAssembly 与 WebGL 2.0；不能据此笼统声称它无法做网页或性能必然不佳。

## 三部分职责

| 部分 | 职责 |
| --- | --- |
| 场景 | 建筑、像素角色、镜头、灯光、天空、云、移动与交互区域 |
| 网页 | 产品详情、导航、真实链接、键盘焦点、加载提示和简化产品列表 |
| 内容与布局配置 | 产品标识、名称、简介、链接、素材；店铺位置、外观、阻挡区与入口 |

产品内容与场景布局分开，以稳定的 productId 关联。场景入口与 HTML 产品列表读取同一份产品数据。增加产品时添加内容与布局配置，特殊外观由店铺组件承担。

产品列表作为普通 HTML 展示，不依赖 3D 初始化成功。场景按需加载；WebGL 不可用或资源失败时仍能访问产品。正式面向搜索分发时，为产品内容补充构建时预渲染与页面元信息；Vite SPA 本身不等于已具备完整 SEO。

## 代码组织方向

- app：网页入口、错误边界、加载与降级。
- world：街区布局、建筑、素材、镜头、角色、输入、碰撞与交互。
- environment：设备时间、美术关键帧、天空与光照。
- ui：产品面板、导航、操作提示和演示控制。
- content：产品内容与布局数据。

这些先作为同一应用内的模块，不拆独立包，不建立通用游戏框架。

## 移动与状态

角色沿地面平面移动，简单矩形或多边形阻挡区即可；入口使用距离或触发区判断。首版没有跳跃、刚体堆叠或复杂地形，因此不需要物理引擎。

输入至少区分浏览小镇、查看产品、演示预览三个状态。打开产品面板时停止角色输入，支持 Esc 返回与焦点恢复。输入框获得焦点时不拦截移动键，失焦时清除按键状态。鼠标点击与键盘进入触发同一个产品动作。

角色位置和云动画等高频数值在渲染循环中更新，不通过 React 每帧刷新网页。React 状态负责当前产品、面板开关等离散变化。只有跨模块状态确实复杂后才增加状态管理库。

## 美术与镜头

采用简化的 3D 建筑和地形，配合像素贴图与二维角色动画；远景可用分层图片。PNG 适合像素素材，GLB 适合导出模型。概念稿指导构图与配色，实际资产需拆分制作，不能把整张概念图当成可以自由行走的三维场景。

先试固定角度正交相机，以店招和角色的实际可读性调整取景。镜头在中央范围内保持稳定，角色靠近边缘才平滑跟随。地图扩展时增加相邻街段，保持观看尺度；后续按街段加载资源。

使用受控的像素渲染分辨率与贴图采样。白天与夜晚都要检查贴图、遮挡和文字可读性。后期辉光谨慎使用，像素清晰度优先。

## 昼夜与演示

昼夜来自设备当地时间，太阳采用每日重复的美术路径，云使用固定规则循环动画。详见 day-cycle.md。

开发演示模式可冻结或加速时间、复位角色和镜头，便于重复录制。加速片段标注为演示；正式默认不改变真实时间流速。录制竖屏时调整取景，保持角色和主店可见。

## 性能与验证

第一版控制场景规模、纹理尺寸、真实光源、阴影与后期效果数量。按设备能力调整像素渲染分辨率；页面隐藏时暂停动画，恢复时重新读取当地时间；减少动态效果偏好下停用装饰性运动。

环境目标暂定为普通桌面流畅、手机可浏览；具体性能目标在第一个真实素材样片上测量后确定，不以概念图推断帧率或包体大小。

验证重点包括：移动和碰撞、门口触发、产品面板焦点与返回、真实链接、午夜过渡、后台恢复、资源失败降级，以及桌面和手机可读性。时间插值与碰撞等逻辑可用 Vitest 做针对性检查，完整入口流程用浏览器验证。

## 交付顺序

1. 初始化 Vite、React、TypeScript、Three.js 与 React Three Fiber，确认依赖兼容，提交锁文件。
2. 一个店铺样片：验证固定镜头、像素素材、日夜灯光和人物尺度。
3. 接通移动、入口触发、产品 HTML 面板与真实链接。
4. 扩到三个店面，补充直接访问、手机取景与降级路径。
5. 加入录制控制，测试后制作演示视频和部署可访问网站。
